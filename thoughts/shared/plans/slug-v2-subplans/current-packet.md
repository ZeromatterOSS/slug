## Background and boundary

Pinned Bazel 9.2 source now closes the full attr-visible loading schema for the
four current Starlark shapes and nine current native classes. Ordinary query
observes fixed, package-computed, macro-derived, automatic, and late-bound
declaration-default loading values, not configured-analysis resolver results.
Whole-value interior order remains observable; candidate position and
multiplicity of equal whole candidates do not. The current V2 projection is
not an implementation boundary: it drops most of this schema and rejects
native toolchain targets before graph projection.

  extend `query-labels-attribute-metadata`, add one isolated fixture, or prove a
  smaller split. Reuse existing labels, modules, packages, and mutations where
  they discriminate the ledger; inventory every new file and row before any
  later generation packet.
- Assign paired positive/negative ordinary-query rows to every accepted ledger
  equivalence class: string/integer/BOOLEAN/license rendering; empty versus
  nonempty containers; null suppression; ordered versus order-independent
  list/map interiors; duplicate elements within one value; and every admitted
  dictionary orientation.
- Cover equal-key selector correlation, distinct-key cross-product, typed
  string/list concatenation, effective defaults, private/implicit query
  spelling, and canonical main/external/`@@bazel_tools` label leaves. Exclude
  candidate position and equal-candidate multiplicity explicitly.
- Cover universal `name`, package visibility/deprecation/testonly/metadata/
  license, legacy macro `generator_*`, test timeout and fixed/late-bound/
  automatic test values, the optional Starlark-transition allowlist, and each
  native inheritance/removal exception. Use equivalence rather than one row per
  redundant empty default.
- Keep native-toolchain graph projection as a separate later prerequisite.
  Design how oracle rows prove the `toolchain` RuleClass surface without
